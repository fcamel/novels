# Commit guidance

## 圖片與漫畫發佈規範

- 控制 Git 儲存庫大小。預設不要將 PNG 原稿、歷次生成圖、審稿候選、比較用圖或中間產物加入 Git。
- 這些產物統一放在已由 `.gitignore` 排除的 `local-production/`；必要的角色設定、校稿規範與正式來源留在 `comics/`，圖片優先使用經使用者確認的 WebP。
- 每次完成漫畫或修改漫畫頁面後，在加入 Git 前，提供原圖與壓縮圖的視覺比較及檔案大小。使用圖片比較工具，至少提供預設 WebP quality 80；可加上 quality 70 供選擇。不要自行認定肉眼沒有差異。
- 必須由使用者決定將原圖或哪個壓縮版本放進 repo。若使用者已明確核准特定圖片與品質，可直接採用，不重複詢問。若使用者決定保留 PNG，尊重其選擇；PNG 不是絕對禁止。
- 未確認的候選圖不得覆寫正式來源、提交或部署。採用壓縮版前，先驗證原稿已保存在 `local-production/`，並確認候選圖與使用者審閱版本一致。
- Git 只收最終採用圖，不收同一頁的歷次版本。不要把尚未核准的 PNG 先提交、之後再刪除；大檔仍會留在 Git 歷史。
- 部署支援 PNG／WebP：PNG 轉 WebP（預設 quality 80、method 6），WebP 正文原樣複製、不再次有損壓縮。縮圖可另產生。網站檔名依清單順序為 `001.webp`、`002.webp`……。
- 發佈只包含正式網站資產；不包含角色設定、製作文件、本機備存或原始 PNG 漫畫。保留必要的角色設定與整體性校稿文件，供後續改編使用。
- 重寫 Git 歷史需使用者明確授權；執行前在 `local-production/` 建立備份，推送使用明確遠端舊提交值的 `--force-with-lease`。
